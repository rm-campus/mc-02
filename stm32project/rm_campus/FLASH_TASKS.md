# 外部 Flash 测试与四轮目标/转速日志

更新：2026-11-13。协议和状态码见 [COMMUNICATION_PROTOCOL.md](COMMUNICATION_PROTOCOL.md)，工程入口见 [README.md](README.md)。

## 配置与任务

当前默认四轮实时调试，两个 Flash 开关均为 0。以下配置互斥：

| 宏 | 实时调试（当前默认） | 四轮离线日志 |
|---|---:|---:|
| MOTOR_DEBUG_MODE | SINGLE 或 FOUR，默认 FOUR | FOUR |
| MOTOR_DEBUG_ENABLE | 1 | 1 |
| MOTOR_DEBUG_TELEMETRY | 1 | 0 |
| MOTOR_SPEED_LOG_TASK_ENABLE | 0 | 1 |
| FLASH_TEST_TASK_ENABLE | 0 | 0 |

宏位于 App/Inc/motor_debug_config.h 和 flash_tasks_config.h。改宏后重新编译烧录。
日志开启时选择 SINGLE 会编译报错；任一 Flash 功能与实时回传同时开启也会报错。
实时单轮仍四列、四轮为九列，均为 200 Hz；Flash 日志是独立的 100 Hz 八列回放。
Flash 测试任务独立开关保留，可与日志共用服务任务，日志本身不需要开启测试任务。

没有新增 RTOS 任务，也不改 .ioc。FlashServiceTask 是实际访问 Flash 的唯一任务，BelowNormal、512 words；
MotorSpeedLogTask 为 Normal、512 words；可选 FlashTestTask 为 Low、512 words。
在 freertos.c 的 USER CODE 内按宏创建。默认均关闭时不创建、不读写或擦除 Flash，只有 motor_status 命令仍有效。
日志 READY/采集时每 1 tick 检查控制快照，采样和回放按 10 ms 节拍；WAIT_READ/ERROR 时等待命令事件。
任务堆继续为 48 KiB；日志 256 条队列使用 8 KiB 静态 RAM（100 Hz 下约 2.56 秒缓存），完整控制快照也使用静态缓冲。

## 硬件与分区

W25Q64JV 为 8 MiB，OCTOSPI2→OCTOSPIM Port 1，PB2/CLK、PE11/CS、PD11/IO0、PB0/IO1、PA3/IO2、PA1/IO3。
保持 10 MHz、Mode 3、普通单线指令、24 位地址；不新增 DMA、Quad 命令或内存映射。

| 地址 | 用途 |
|---|---|
| 0x000000–0x000FFF | 独立 Flash 测试扇区 |
| 0x001000–0x001FFF | 日志信息：格式、周期、条数、方向、完成/擦除标记、记录长度 |
| 0x002000–0x7FFFFF | 日志数据 |

首次遇到空白日志头先准备首个数据扇区；其余扇区按需擦除。驱动保持写后读回校验、擦后全 FF 检查，
等待 Flash 时让出 CPU。读取完整日志不依赖采样 RAM；不执行整片擦除，测试扇区不受日志清理影响。

## 数据来源与触发

日志在自己的任务内调用 Campus_CopyMotorStatus，取得同一临界区复制的控制、遥控和电机快照。
目标取 debug.wheel[i].control.target（rad/s），四路分别换算为输出轴 rpm；反馈取 motors.rotor_rpm[i]。
各电机反馈来自异步 CAN 帧，快照不代表物理采样时间完全相同。
不再覆盖 Fxi6x_OnFrame，也不依赖 Chassis_SetTargetWheelRpm。后者作为预留接口保留。
后续底盘加入运动学时应维护四轮真实目标和运行状态；日志不包含麦轮解算。

READY 且控制快照新鲜有效、遥控有效、拨杆 -1 时，四台均 RUNNING 且任意目标非零即开始。
正负均可，零摇杆不妨碍非零控制目标触发；首次 READY 已满足条件也会启动，不需要遥控边沿。
不覆盖待回放日志。记录完成、回放、擦除后，如果条件一直成立则等待其解除再成立，避免连续运动反复录制。

反馈年龄 <100 ms 才在线，直接引用控制的反馈超时宏。离线速度写零；故障但仍在线的电机记录实际速度。
单轮故障不停止整组日志；停止控制后的目标按控制快照记录（当前控制清零），不复制公共目标冒充历史目标。

## 结束条件

- 四台在线且 RUNNING，首次同时达到各自当前目标后再记录 5000 ms，之后目标/反馈变化不重置计时。
- 四路目标全零立即结束，先判定再采样，排除后续减速过程。
- 拨杆退出 -1、遥控失联、控制快照 >=100 ms 未更新、全部退出 RUNNING 或目标非法时提前结束。
- 空间满、256 条队列满或漏过完整 10 ms 采样周期时停止并保存已有记录，不伪造时间连续性。

达标容差 max(1 rpm, |各自目标|×2%)；至少一路目标非零，非零目标要求实际速度非零且同方向。
若某轮故障且尚未首次达标，待四台重新在线并 RUNNING 才能满足达标；也可令目标全零/关拨杆结束。
日志不发电流指令、不增加控制运行时限；达到上述条件只结束日志。

## MLG2 存储格式

每条 32 字节，小端编码：0～15 为四个 int32 目标（0.001 输出轴 rpm）；16～23 为四个 int16 原始转子 rpm；
24～31 为 FF 预留。每个 256 字节页装 8 条完整记录，记录不会跨页或扇区。
不记录逐条时间戳、反馈年龄、有效掩码或 CRC32。反馈原始值保存时不除减速比、不应用方向。
正常结束时写完最后不足一页的数据，再写条数及完成标记。100 Hz 下整个日志区可容纳 261888 条，约 43.6 分钟。

信息头为 32 字节：magic=MLG2、新日志周期=10 ms、条数、方向掩码、完成/擦除标记、记录长度=32，其余预留。
已保存的 50 Hz MLG2（20 ms）保持兼容，按原周期回放。写擦除标记时也保留原周期，避免 NOR 的 0->1 改写；
清理完成后恢复 10 ms，新一轮记录按 100 Hz。status 的 period_ms 显示当前日志周期。
旧版 MLG1 只有反馈而没有目标，启动报 LOG error=103 并保留数据，不允许直接 read。
如需旧记录先用旧固件导出；确认可丢弃后 clear。非法头 error=100、未完成记录=101、记录中方向改变=102。
完整 MLG2 日志可跨重启回放；录制中断电不承诺恢复，无 CRC 不提供数据损坏检测保证。

## USB 命令及八通道回放

使用原生 USB CDC，线路设置可保持 115200/8N1；它不是实际 USB 传输速率限制。
命令区发送 ASCII 和真实 LF（也接受 CRLF），按换行分帧，支持 USB 拆包/粘包。

| 命令 | 行为 |
|---|---|
| read | WAIT_READ 时从 Flash 开头读取，按原采样周期回放八列 CSV（新日志 100 Hz） |
| status | 查询 Flash/测试/日志状态、已落盘条数、停止原因、目标有效、达标标志和 period_ms |
| clear | READY、WAIT_READ 或 ERROR 时丢弃并擦除日志分区，保留测试扇区 |
| motor_status | 保留现有诊断，输出等待 Flash 事务释放 USB |
| flash:<内容> | 仅独立测试开关开启时：写 Flash、清空输入缓存、读 Flash 回传、发送完成后擦除 |

日志回放顺序是目标1、实际1、目标2、实际2、目标3、实际3、目标4、实际4：

```text
225.000,221.500,-225.000,-223.100,100.000,98.800,-100.000,-99.600
```

八列均为输出轴 rpm，三位小数、逗号分隔、LF 结束，无 speed:、表头、ready 或完成提示。
四路目标和反馈均取自本次 Flash 读取；实际速度除以减速比 3591/187 并应用日志头方向，目标不再换算方向。
电脑用纯 CSV 绘图，间隔取 status.period_ms（新日志 10 ms，旧 50 Hz MLG2 为 20 ms）。
USB 忙时等待，不丢条目，也不突发追赶；正常 10 秒记录约回放 10 秒。

最后一帧 UsbSerial_SendTracked 的凭据确认实际完成后才标记擦除中，逐扇区清理数据，最后擦除信息区。
断线/会话改变时停止回放并保留 Flash，再次 read 从头播放。USB 完成不等于电脑软件保存成功，没有应用层 ACK。
擦除标记持久化后，重启可继续自动清理；手动 clear 中途断电不承诺自动完成整区清理。
Flash 事务占用 USB 时普通 status/提示可能被抑制，motor_status 等待输出；不插入八列数据中。
测试事务原有行为完整保留，单行上限 4096 字节；回传来自实际 Flash 读取，不使用原输入副本。

## 验证

主机回归运行 tests/run_flash_tests.py：真实驱动命令、模拟 NOR、延迟写入/擦除和 USB 完成，覆盖四种任务开关，
正负目标、四台 RUNNING、逐轮历史目标、动态达标、100 ms 离线、单轮故障、全零/拨杆/失联/超时停止，
跨页/跨扇区、队列溢出、容量、回绕、旧格式保护、重启恢复、断线重放与最后一帧完成后擦除。
回放测试会改变 Flash 中的目标和转速，再检查 CSV，确保不使用采样 RAM。
另验证 10 秒 1000 条/100 Hz 回放，以及旧 50 Hz MLG2 的读取、原速回放、擦除中重启与新记录周期恢复。
还需运行 motor_debug 回归以验证实时单轮四列/四轮九列及 200 Hz 行为；分别编译实时与离线配置。
主机测试与编译不等同上板验收，实际 Flash 擦写、USB 绘图和任务栈高水位仍需实机验证。
