# 外部 Flash 测试与四轮转速记录

完整命令、全部返回文本、状态码及 VOFA 操作流程见 [COMMUNICATION_PROTOCOL.md](COMMUNICATION_PROTOCOL.md)。
工程交接与构建说明见 [README.md](README.md)。

## 开关与任务

当前为单电机实时调试，`App/Inc/flash_tasks_config.h` 中两个开关默认均为 `0`，功能代码完整保留：

```c
#define FLASH_TEST_TASK_ENABLE       0
#define MOTOR_SPEED_LOG_TASK_ENABLE  0
```

当前不创建下列三个任务，不读写或擦除 Flash，`read/status/clear/flash:` 命令没有回应。
`motor_status` 是独立诊断命令，始终可用。Flash 输出事务期间诊断等待释放 USB，再发送一份请求时快照。
实地记录时先把 `motor_debug_config.h` 中 MOTOR_DEBUG_TELEMETRY 置 0，再开启所需 Flash 开关。
编译检查禁止两种回传模式同时启用。以下说明适用于重新开启 Flash 功能后。

- `FlashTestTask`：Low 优先级，512 words 栈，接收请求后进行 Flash 写入、读取、回传和擦除。
- `MotorSpeedLogTask`：Normal 优先级，512 words 栈，处理摇杆触发、50 Hz 采样、停止判定和回放。
- `FlashServiceTask`：BelowNormal 优先级，512 words 栈，所有外部 Flash 操作的唯一执行者。

任一开关为 1 时创建 Flash 服务；两者均为 0 时上述三个任务都不创建。创建入口放在
`freertos.c` 的 `USER CODE BEGIN RTOS_THREADS` 中，独立于 CubeMX 无条件创建的原有任务。
新增任务通过事件唤醒，活动状态下以 1 tick 服务状态机；采样/回放由 20 ms 时基限定。
FreeRTOS 堆已由 32 KiB 调至 48 KiB。页缓冲、测试接收区和日志队列采用静态分配。

## 硬件与分区

W25Q64JV：8 MiB；OCTOSPI2 经 Port 1 接 PB2/CLK、PE11/CS、PD11/IO0、PB0/IO1、
PA3/IO2、PA1/IO3，10 MHz、Mode 3。驱动先使用单线 24 位地址指令，不依赖 Quad Enable、
DMA 或内存映射。HAL OCTOSPI 源码来自本机 STM32Cube FW_H7 V1.12.1。

| 地址 | 用途 |
|---|---|
| `0x000000–0x000FFF` | 独立测试扇区，4 KiB |
| `0x001000–0x001FFF` | 日志信息：格式、20 ms 周期、条数、方向配置、完成/擦除状态 |
| `0x002000–0x7FFFFF` | 日志数据 |

不执行整片擦除。首次遇到空白日志信息区时准备首个数据扇区；其它数据扇区在第一次写入前
按需擦除。擦除由服务任务执行，采样任务继续往 2 KiB RAM 环形队列写入。
写入按页拆分，等待 WIP 清除后读回比对；擦除后检查扇区全为 FF。驱动有地址范围、写使能、
保护位、超时和 JEDEC ID 检查，接受 `EF 40 17` 与 `EF 70 17`。

## USB 命令

使用 MCU 原生 USB 的 CDC 串口。VOFA 选择 FireWater，界面线路参数可用 115200/8N1/无流控。
命令区须发送真实 LF 换行（也接受 CRLF），不要发送字面字符 `\\n`。
同一条命令可跨多个 USB 包，多条命令也可以在一个包里。重新枚举/挂起时清除未完成的接收行。

| 命令 | 行为 |
|---|---|
| `flash:1,2,3,4` 加换行 | 原样写入测试扇区，再从 Flash 读取并原样回传；完成后擦除测试扇区 |
| `read` 加换行 | 在一轮记录结束后，以 50 Hz 回放该轮日志 |
| `status` 加换行 | 查询 Flash、测试任务、日志状态和错误 |
| `clear` 加换行 | 显式放弃并擦除整个日志分区；只在空闲、待回放或错误状态接受 |

单次 `flash:` 行连同前缀和换行最多 4096 字节；超限整行拒绝。Flash 测试是按行字节读写测试，
发送符合 FireWater 的数值行可以直接在 VOFA 查看。测试接收缓冲在写完后清零，回传数据只取自
随后执行的 Flash 读取。测试分区和日志分区完全分开。

USB 回传任务互斥：Flash 测试回传进行时不能启动日志回放；日志回放期间不能插入测试帧或状态输出。
电机采样可以与 Flash 测试并行，底层操作由服务队列串行化。发送忙时保留数据，不忙等、不丢帧补发。

`UsbSerial_SendTracked()` 返回的凭据包含会话号和会话内完成位置。只有 USB 完成回调确认最后一条
数据已传输，才能开始发送后的擦除。入队成功不是发送完成；会话变化不会误用旧完成计数。
USB 传输完成并不证明 VOFA 已保存到电脑文件，协议没有应用层 ACK。

## 记录触发、数据及停止

有效新遥控帧中，CH4/左水平或 CH2/左竖直任意一轴由精确 0 变成非 0，触发一轮。
首个有效帧只建立基线；录制、待回放、回放、擦除期间不会覆盖上一轮。任务重新就绪后需要新的边沿。
没有新增死区。双轴同时回零时先停止采样，再处理缓存，不把后续减速过程写入。

每 20 ms 记录四台 C620（ID 1–4）的原始转子 rpm，格式为四个小端 `int16_t`，每条 8 字节。
不保存逐条时间戳、反馈年龄、有效掩码或 CRC32。首次尚未收到反馈或超过 50 ms 未更新的电机写 0。
原始值不应用方向翻转。正常结束时刷新最后不足一页的数据，然后写入记录条数和完成标记。

停止条件：

1. 四台均在线，当前目标有效且至少一台目标非零，各轮反馈换算成车轮 rpm 后同时进入各自当前目标的容差。
   首次满足时锁定时刻，再记录 5000 ms。此后目标或反馈变化不重置该时刻。
2. 左摇杆双轴提前回零，立即结束本轮。
3. 遥控失联、空间满、采样队列满或漏过一个完整采样周期时，提前停止并保存已采集数据，避免悄悄压缩时间轴。

误差容差为 `max(1 rpm, abs(target) × 2%)`，可在配置头文件中调整。非零目标要求反馈非零且同方向；
离线电机虽然在记录中写 0，但不能通过达标判定。方向配置在记录中途改变会报错。
记录任务只观察数据，不控制电机，也不发送制动指令。

## 后续底盘目标接口

当前 `Campus_ChassisTask` 依然只发送零电流，没有加入运动学/PID。真实目标由后续底盘模块在每帧发布：

```c
#include "chassis_targets.h"

/* target 为实际用于四轮控制的当前目标，ID 1～4，车轮输出轴 rpm；
 * 符号与 motor.velocity[] 保持一致，包含混控、限幅与方向约定。 */
Chassis_SetTargetWheelRpm(target);

/* 禁用底盘或目标不再有效时调用。 */
Chassis_InvalidateTargets();
```

超过 100 ms 未刷新或包含非有限值的目标无效。目标未接入时仍能记录与回放，但不会误触发达标计时；
可以松杆回零结束。不要用四个占位零值伪装真实目标。

## FireWater 回放与清理

回放重新通过 OCTOSPI 读取 Flash 数据，RAM 只缓存当前读取页。每 20 ms 发送一条：

```text
speed:187.000,-187.000,374.000,0.000
```

四个通道依次为电调 ID 1～4。由原始转子 rpm 除以 `3591/187`，再应用本轮保存的方向配置，得到
减速箱输出轴/直连车轮 rpm，保留三位小数。输出采用整数定点格式化，不依赖 newlib-nano 的 `%f`。
如车轮还有额外传动比，需要相应修改换算。VOFA 时间轴设为 50 Hz；录制 10 秒正常回放也约 10 秒。

读取过程中 USB 断开/挂起或重新枚举：停止本次回放，保留日志；待 USB 旧队列排空后重新发送 `read`，
从第一条重新开始。Flash 测试则在连接恢复、旧队列排空后自动从头重传测试数据。

最后一帧完成后先持久化“擦除中”状态，再逐扇区擦除本轮数据，最后擦除日志信息区，随后进入 READY。
正常完成的日志可以在 MCU 重启后回放；擦除中重启会继续清理。录制或最终信息写入途中断电不承诺恢复，
没有 CRC 的文件也不提供数据损坏检测保证；不完整/非法日志头报错并保留现场，可用 `clear` 恢复。
`clear` 会擦除整个日志分区，可能持续数十秒到数分钟；测试扇区不受影响。

## 状态与验证

日志 `state`：0 BOOT、1 PREPARING、2 READY、3 RECORDING、4 FLUSHING、5 WAIT_READ、
6 REPLAYING、7 ERASING、8 ERROR。
`stop`：0 无、1 松杆、2 首次达标后 5 秒、3 遥控失联、4 空间满、5 队列满、6 采样超期。
日志 `error`：100 非法文件头、101 未完成记录、102 中途改变方向；1000+驱动错误码表示 Flash 故障。
驱动错误码：1 参数、2 通信、3 超时、4 ID、5 写保护、6 读回校验失败。
测试 `state`：0 IDLE、1 LOADING、2 WAIT_SERVICE、3 ERASE_FIRST、4 WRITE、5 READ、
6 SEND、7 WAIT_TX、8 ERASE_LAST、9 PAUSED、10 ERROR。`status` 在回传占用 USB 时不插入输出。

主机回归：`python tests/run_flash_tests.py`，测试 W25 命令时序、跨页写入、保护/超时、真实读回路径、
50 Hz 记录和 FireWater 回放、当前目标更新、四轮在线条件、回零/失联/满空间停止、USB 完成后擦除、
断线重连、计时回绕、已完成日志恢复及四种开关组合。`tests/run_usb_serial_tests.py` 另外验证真实 USB
BSP 的完成凭据、ZLP 和会话重置。测试不连接板卡、不擦除实际硬件。

上板仍需确认 JEDEC ID、实际擦写、四轮方向/轮位、VOFA 曲线及任务栈高水位。尚未实现底盘闭环，
不要把日志功能的完成理解为已有遥控驱动车轮功能。
